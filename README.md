# Касса Control

Рабочая станция администратора касс Set Retail: кроссплатформенное десктопное
приложение (PySide6) для удалённого обслуживания кассовых систем через SSH,
SFTP, VNC и SQL, со сводным диагностическим отчётом и набором команд
перезапуска по кнопке.

Это не прототип и не макет: в приложении нет демо-транспорта и подставных
данных. Все сведения берутся с реальной кассы по открытому SSH-соединению.

## Возможности

- **Список касс** слева: имя, адрес, тип (POS / SCO / Touch / Hybrid), статус
  соединения. До 10 одновременных сессий.
- **Сводная информация** справа: карточки «Версия ПО», «Сервер SET», «Статус»,
  «БД / порт» и разделы «Кассовое ПО», «Сеть», «БД и данные», «Железо»,
  «Диски», «Аппаратные компоненты», «Версии jar-файлов».
- **Команды по кнопке**: «Перезапустить кассу» (`cash restart`), «Полная
  перезагрузка» (`sudo reboot`), «Перезапустить ОФД» и ещё 18 безопасных
  проверок. Команды с риском `danger` и `critical` требуют подтверждения.
- **SSH-терминал** — настоящий PTY на `pyte`, а не имитация приглашения.
- **Файловый менеджер** — локальный диск и касса через SFTP, перенос файлов
  в обе стороны, встроенный редактор.
- **База данных** — SQL-консоль над PostgreSQL кассы и над локальным SQLite,
  дерево схемы, предпросмотр таблиц, выгрузка в CSV.
- **VNC** — собственный клиент RFB 3.8 (Raw, CopyRect, RRE, Hextile, ZRLE,
  в том числе с VNC-аутентификацией), без QWebEngine и без noVNC.
- **Туннели** — локальный и удалённый forward, цепочки jump host, проверка
  занятости портов до подключения.
- **Пароли** не хранятся в файлах профилей: сначала системный keyring
  (Windows Credential Manager / Secret Service / macOS Keychain), при его
  отсутствии — файл, зашифрованный Fernet, с ключом `0600` рядом.
- **Логи** — журнал приложения с фильтром по уровню и выгрузкой, рядом
  список команд каталога категории «Логи»: вывод `crystal-cash`, ошибок за
  сегодня и системного журнала приходит с кассы по SSH.
- **Настройки** — тема, значения по умолчанию для новых подключений,
  таймауты, проверка ключа хоста, показ активного хранилища паролей и
  каталогов приложения; всё пишется в настоящий `settings.json`.
- **Три темы** — тёмная, светлая и серая. Это три набора токенов поверх
  одного QSS-шаблона, а не три копии стилей.

Данные о процессоре и памяти **рабочей станции** намеренно не показываются:
в отчёте остаётся только компактный раздел `[[6.0 Платформа]]` по кассе.

## Сводный отчёт

Отчёт собирается 32 пробами, выполняется на кассе по SSH и отображается в
панели справа, которую можно отцепить в отдельное окно. Разделы:

```
1     Информация по времени
2     Статус работы кассового модуля        2.1  cash status
2.2   Службы ОФД                            2.3  Версия кассы и Java
3     Размер папок кассового модуля         3.1  Размер баз данных
4.8   Загруженные банки                     4.8.2 Папки и права банков
4.9   Внешние процессинги                   4.11  Загруженное оборудование
4.11.1 Задействованное оборудование         4.13  УТМ ЕГАИС
4.14  Сервер SetRetail                      5.1   Статус МУК
5.2   Патчи обновлений                      5.3   Бэкапы
6.0   Платформа                             6.1   Сетевые подключения
6.1.1 Подключённые хосты                    6.1.3 Открытые порты
6.1.4 Таблица маршрутизации                 6.2   Перезагрузки ОС
6.3   Версия ядра                           6.4   Архитектура
6.8   Файловые системы                      6.9   Разделы
6.10  COM-порты                             6.11  USB
6.12  Жёсткие диски                         6.13  SMBIOS/DMI
7     Версионность jar-файлов (modules)
```

Из текста отчёта выделяются факты (`cash status` → версия, POS Loaded,
IP, gateway, размер БД, свободное место, адрес и статус сервера, состояние
модуля), и именно они наполняют карточки обзора.

## Расширение без правки кода

- `commands.json` — свой каталог команд; `CommandCatalog.load()` принимает
  путь, совпадение по `id` заменяет встроенную команду.
- JSON с пробами — `load_custom_probes()`; совпадение по номеру раздела
  заменяет встроенную пробу.

## Установка и запуск

```bash
python3 -m pip install -e ".[qt,ssh,secure,db]"
python3 -m cashdesk_control
```

Без PySide6 или `qasync` приложение отказывается стартовать (код возврата 2)
и сообщает, какой extra установить, вместо того чтобы открыть окно, которое
не сможет подключиться.

### Windows 10/11

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build_windows.ps1
```

Результат — `dist\CashdeskControl\CashdeskControl.exe` и архив
`dist\CashdeskControl-windows-x64.zip`. Настройки и логи живут в `%APPDATA%`,
пароли — в Windows Credential Manager. Подробности: `packaging/windows/README.md`.

Тот же onedir-сбор собирается workflow `Windows application` на
`windows-latest`: установка зависимостей → `pytest` → PyInstaller → проверка
наличия `.exe` → артефакт.

## Тесты

```bash
python3 -m pytest tests -q
```

140 тестов. Из них 17 выполняются против настоящего `sshd` (подключение,
коды возврата, таймаут, SFTP, PTY, реальный проброс порта, сбор отчёта,
туннели) и 21 строят настоящее окно в offscreen-режиме и проводят его через
добавление профиля, подключение, команду, сбор отчёта, получение логов с
кассы и смену темы. Интеграция
по SSH включается переменными окружения и пропускается без них:

```bash
CASHDESK_TEST_SSH_HOST=10.162.1.3 CASHDESK_TEST_SSH_PORT=22 \
CASHDESK_TEST_SSH_USER=tc CASHDESK_TEST_SSH_KEY=~/.ssh/id_rsa \
CASHDESK_TEST_SSH_KNOWN_HOSTS=~/.ssh/known_hosts \
python3 -m pytest tests/test_ssh_integration.py -q
```

## Прототип

`prototype/` — прежний статический макет на `index.html` / `styles.css` /
`app.js` с Kubernetes-манифестом. Он оставлен как визуальный ориентир для
десктопного интерфейса и **не является продуктом**: данные в нём подставные.

```bash
python3 -m http.server 4173 --bind 0.0.0.0 --directory prototype
kubectl apply -f prototype/simple-web.yaml   # при желании
python3 scripts/sync_manifest.py             # пересобрать ConfigMap после правок
```
